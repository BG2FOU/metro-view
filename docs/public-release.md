# 自动发布到公开仓库

源仓库的 `public/metro-view` 分支由 `.github/workflows/release-public.yml`
自动发布到 `BG2FOU/metro-view` 的 `main` 分支。

## 增量发布

- 提取本次脱敏提交的文件树，排除源仓库专用的发布工作流。
- 获取公开仓库 `main`，以它为唯一父提交创建新提交。首次发布到空仓库才创建根提交。
- 内容相同时跳过提交与推送；新增、修改、删除和文件模式变化按正常 Git 差异记录。
- 使用普通快进推送，保留既有公开历史；并发更新会使推送失败，不强制覆盖。
- 脱敏分支提交及其私有祖先不会作为父提交进入公开仓库。
- 保留脱敏源提交的作者、提交者、时间和完整提交消息，追加 `Public-Source-Commit` trailer。
  发布提交消息本身也必须使用可公开的描述。

从旧的单根快照迁移时，新提交直接接在当前公开快照后面，不需要重建公开仓库。
公开仓库仍作为镜像维护；直接在公开仓库修改文件会在后续同步时被脱敏分支内容替换，
需要先把相关修改带回脱敏分支。

## 配置与检查

在源仓库 Actions Secrets 中配置 `PUBLIC_REPO_METRO_VIEW_TOKEN`，仅授权
`BG2FOU/metro-view` 的 `Contents: Read and write`。不要把 token 写入代码或日志。
向 `public/metro-view` 推送即可触发发布，也可在该分支手动运行工作流。
其他分支的手动运行不会发布。

发布前检查私有文件和运行标识，执行类型检查、合成运行图一致性检查、单元测试、
构建及浏览器测试。推送前再次检查源分支，跳过已被新提交取代的旧运行。
`scripts/publish-public.sh` 的本地 Git 集成测试覆盖初次发布、增量同步、无变化跳过、
删除及文件模式变化、并发冲突拒绝和私有历史隔离。
